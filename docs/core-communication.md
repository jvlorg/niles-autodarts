## Current component lifecycle and remaining contract gaps

Before opening a stream, the component validates the configured Board Manager endpoint and its matching host permission grant. Host-managed WebSocket callbacks pass event JSON into the owned session. HTTP `/api/state` polling remains a separate status path and is not promoted to score ingress. Reconfiguration resets announcement policy and stream resources; connection-status changes reset policy and require a new clean baseline. The component opens and uses the configured room speech stream for eligible requests, reports unavailable resources or failed submissions explicitly, and closes active resources during cleanup. See [`lib.rs`](../component/src/lib.rs) and the synthetic import implementations in [`test_host.rs`](../component/src/test_host.rs).

The session parses and invalidates automatically on malformed JSON; callbacks must not silently drop parse failures. Nonempty snapshots suppress the entire existing collection and later appends. Only a clean empty/count-zero state restores eligibility. Delivery request keys include connection epoch and collection serial, and attempts are recorded before adapter invocation, preventing blind retries. These semantics do not assert exactly-once audible delivery. The room-bound seam exists, while released-host compatibility, actual target selection/authorization for a persisted selected-satellite subset, and audible routing are not established here.

## Candidate total and order policy

The local contract is per-dart announcements as the API reports them in Each dart → Total mode, and no dart announcements in TotalOnly. The first `motion_state.isTakeoutPartial == true` or `isTakeoutFull == true` completes an eligible cached local collection once; a later partial/full marker is suppressed. This local detection total is not a game-authoritative score or game-turn judgment. If throws shrink/clear first, retain a bounded last validated pre-removal snapshot; shrink by itself never announces, but a later explicit marker can complete that snapshot. TotalOnly clear-before-marker also preserves the eligible cached collection and remains silent until the explicit marker. If evidence suggests correction, is invalid/out-of-order or otherwise ambiguous, suppress. After removal/clear, require a clean empty count-zero baseline before another collection. Source events provide no reliable timestamps, so no timestamp semantics are inferred. These are add-on policy rules, not proven universal Board Manager semantics or live compatibility.

Target lists are sorted and deduplicated. Delivery attempt keys include connection epoch and collection serial and are recorded before calling the adapter, preventing an uncertain failure from being retried as definitely unheard. Disabled intent, mode/audience change, and reconnect reset the reducer and require a new clean empty baseline. Recording-adapter proof is add-on policy only, not host transport or speech proof.
