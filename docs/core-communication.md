# Add-on ↔ Niles core communication inventory

Scope: checked-in add-on sources and pinned WIT contract. Niles household membership, audience resolution, room/satellite authority and speech delivery remain core-owned. The imported WebSocket and room speech-stream contracts below are implemented by the component; their synthetic coverage does not establish installed-host compatibility or selected-satellite routing.

| Boundary | Direction and payload | Status / owner | Limits and proof |
|---|---|---|---|
| Lifecycle | Core invokes component lifecycle exports | Implemented via pinned WIT | Synthetic component tests and local synthetic-host check only |
| Configuration | Core config supplies Board Manager address, room, poll interval, announcement enabled/mode/audience | Implemented parsing; Niles owns persistence | Disabled by default; audience identities are opaque intent, not resolved/authorized satellites |
| HTTP state | Add-on → Board Manager GET `/api/version`, GET `/api/state` | Implemented status poll | Timer poll is not an event feed; snapshot handling does not announce existing darts |
| Detection control | Add-on → Board Manager bodyless PUT `/api/start` or `/api/stop`, then state reread | Implemented | Detection only; no reset/game start; synthetic callback tests only |
| Event provider | Board Manager → add-on `/api/events` WebSocket `{type,data}` envelopes | Component opens the connection when announcement intent is enabled and forwards active-connection text frames of at most 64 KiB to `AnnouncementSession::ingest_json`; non-text and oversized frames are invalidated | Synthetic callback tests exercise stale-connection filtering, valid text, binary/malformed-frame invalidation and reconnect resets. Oversized-frame rejection and overflow resets are source-implemented without dedicated callback tests; live event order and miss encoding remain unverified |

## Active event and speech path

The component owns the WebSocket connection and accepts callbacks only from its active connection. It sends bounded text envelopes to `AnnouncementSession`; non-text and oversized frames invalidate the journey instead of being silently dropped. Connected, disconnected, failed and overflow status callbacks reset the session baseline. The pinned WebSocket import and component callback tests are documented in the published [component runtime](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/src/lib.rs#L658) and [callback tests](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/src/tests.rs#L329).

The component opens speech only when `speech_stream_enabled` is set, using the configured room declared by the [published manifest](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/niles-integration.toml). Its `AnnouncementDelivery` submits text, associates returned host request IDs with policy deduplication keys, polls request status on the component timer, and closes the session on stop. The pinned interface is in the [published WIT](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/wit/niles-integration.wit); mock imports are in the [published test host](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/src/test_host.rs#L166). This establishes the component wiring and synthetic behavior, not compatible installed-host operation or audibility. The core trait still carries configured opaque identities, but the room-bound import does not establish that selected-satellite audience intent is honored. Niles must retain household resolution, authorization and speech authority.

HTTP `/api/state` snapshots remain status/baseline information and are not promoted to real-time append events. Detection start/stop controls Board Manager detection only; it is distinct from physical power, reset and game creation.

## Candidate total and order policy

The approved local contract is per-dart announcements as the API reports them in Each dart → Total mode, and no dart announcements in TotalOnly. The first `motion_state.isTakeoutPartial == true` or `isTakeoutFull == true` completes an eligible cached local collection once; a later partial/full marker is suppressed. This local detection total is not a game-authoritative score or game-turn judgment. If throws shrink/clear first, retain a bounded last validated pre-removal snapshot; shrink by itself never announces, but a later explicit marker can complete that snapshot. TotalOnly clear-before-marker also preserves the eligible cached collection and remains silent until the explicit marker. If evidence suggests correction, is invalid/out-of-order or otherwise ambiguous, suppress. After removal/clear, require a clean empty count-zero baseline before another collection. Source events provide no reliable timestamps, so no timestamp semantics are inferred. These are add-on policy rules, not proven universal Board Manager semantics or live compatibility.

Target lists are sorted and deduplicated. Delivery attempt keys include connection epoch and collection serial and are recorded before calling the adapter, preventing an uncertain failure from being retried as definitely unheard. Disabled intent, mode/audience change, and reconnect reset the reducer and require a new clean empty baseline. Recording-adapter proof is add-on policy only, not host transport or speech proof.
