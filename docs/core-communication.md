# Add-on ↔ Niles core communication inventory

Scope: checked-in add-on sources and the pinned Niles integration 0.5.0 WIT contract. The provider owns Board Manager communication and local announcement policy. Niles owns household room/audience resolution and speech transport. This source inventory does not establish a compatible installed host or live operation; see the [canonical plan](plan.md#verification-and-proof-boundaries) for the evidence ledger and remaining work.

## Implemented event and delivery path

When announcements are enabled, initialization opens the configured Board Manager WebSocket path. Text callbacks for the current connection identity are bounded to 64 KiB and passed to the session; non-text and oversized input invalidate through the malformed-input path. Connection status changes reset the journey and require a new clean baseline. Stop/reinitialization closes active WebSocket and speech sessions. These lifecycle behaviors have mock-import coverage; they are not guarantees of recovery from every real transport failure.

The session parses `{type,data}` envelopes, applies the local collection policy, and records each delivery attempt before invoking its adapter. Keys include connection epoch and collection identity; configured targets are sorted and deduplicated. Unavailable or failed attempts are not blindly retried. The component adapter submits an utterance through Niles and polls outcomes. An accepted request or transport result does not establish that a person heard it.

A clean empty/count-zero state is required to establish a baseline. A nonempty starting state suppresses that entire existing collection and its later appends. Unrelated camera/status topics are ignored. The reducer accepts one append at a time, at most three darts. Each dart → Total speaks local darts as reported, while Total only remains silent until the first explicit `isTakeoutPartial == true` or `isTakeoutFull == true` marker completes an eligible cached collection once. Duplicate markers do not repeat it. These local values and sums are not X01 remaining scores, busts, checkouts, game selection, match outcomes, or special/game speech.

For marker-before-clear, the validated cached collection completes once. In TotalOnly, clear-before-marker preserves the eligible collection and clear itself does not announce. For Each dart → Total, shrink/empty before the marker retains only the last validated pre-removal snapshot as a bounded candidate; shrink alone never announces. Corrections, invalid/out-of-order or malformed/stopped input, reconnect, disabling, and settings changes invalidate ambiguous candidates. Completion requires a clean empty baseline before another collection. No time expiry is inferred because source events provide no reliable timestamps. Real Board Manager ordering and miss encoding remain unverified; multiplier zero is rejected, and `(0,0)` versus `(0,1)` remains unresolved.

## Product boundary and remaining proof

V1 is local Board Manager detection on/off, room selection, and local announcements in Each dart → Total and Total only modes. Detection on/off does not control physical power/reset or create a game. Room targeting and both announcement modes remain subject to product and live validation; V2 TV scoreboard and V3 game selection remain later roadmap scope. The optional compiled-component host proof and synthetic status checks are described in the [canonical evidence ledger](plan.md#verification-and-proof-boundaries). Neither synthetic host imports nor local HTTP status checks establish installed-host compatibility, live board events, satellite behavior, or audible playback.

No add-on path may bypass Niles with direct satellite transport, a sidecar, notification fallback, or private host functions. Provider behavior stays in this add-on; household and speech authority stay in Niles.
