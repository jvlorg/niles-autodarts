# Announcement-path feasibility

Status: the checked-in component imports provide a room-bound Niles speech-stream path, with synthetic coverage for its lifecycle and request wiring. This is not proof of compatible installed-host operation, selected-satellite routing or audible output. See the [canonical plan](plan.md) for announcement modes, policy and remaining audience work.

## Current component path

The component connects to the Board Manager `/api/events` WebSocket when announcement intent is enabled. Separately, `speech_stream_enabled` gates opening a speech session for the configured room. The component submits requests generated by the transport-independent `AnnouncementSession`, associates returned host request IDs with policy keys, polls request status on its timer, and closes the speech session on stop. The HTTP `/api/state` timer poll remains status/baseline-only and does not provide event ingress.

These capabilities are defined by the published [component runtime](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/src/lib.rs#L417), [component callback tests](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/src/tests.rs#L329), [synthetic WIT imports](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/src/test_host.rs#L166), [pinned WIT](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/wit/niles-integration.wit), and [manifest](https://github.com/jvlorg/niles-autodarts/blob/c0e6b23629914e371c7e2525b4c9c1d972fcf3b9/component/niles-integration.toml). The callback tests observe fake host calls. The optional runtime host proof uses synthetic events and recording speech; the HTTP diagnostic covers synthetic status/render only. Neither is live or audible evidence. A room-bound stream does not prove that opaque configured audience identities resolve to a selected satellite subset, so that product requirement remains unresolved and Niles-owned.

## Actual host route (private functions)

Main follow-up: fetched `origin/main` and independently inspected its WIT at `2f4d54b739e001d2e4e1fe4e173bf4400dae476a` without changing the checkout. The newer contract adds MQTT, secrets and inbound interfaces, but its full plugin import list still has no dedicated announcement/Piper/satellite audience interface. `notify.say` remains explicitly notification delivery (lines 389-406), not the requested announcement contract. This updates the contract check only; internal transport references below remain pinned to the local source revision above. New ingress capabilities deserve separate assessment before concluding event delivery is blocked.

- `crates/niles-bin/src/main.rs:1312-1410`: `WyomingDelivery` implements the notification delivery callback. It resolves a room, uses the live peer when present, otherwise selects the configured IP, synthesizes via Piper and decodes/resamples PCM.
- Live connection: `crates/niles-bin/src/speak.rs:386-415`, `speak_back`, performs Piper synthesis, WAV→PCM conversion, satellite format/volume processing and `WyomingSender::send_audio_then`.
- Idle satellite: `crates/niles-bin/src/push.rs:22-87`, `speak_to`, connects to configured satellite IP on port 10301 and writes Wyoming AudioStart/AudioChunk/AudioStop. Caller is `main.rs:1388-1404`.
- Live Wyoming transport: `crates/niles-wyoming/src/server.rs:219-301`, `WyomingSender::send_audio_then`.
- `crates/niles-bin/src/satellites.rs:11-87`, `SatelliteRegistry`, maps configured IPs to room and volume; `ip_for(room)` returns one configured IP. The inspected route is room resolution, not a persisted selected-subset or satellite-ID audience API.

These implementation symbols are host-internal Rust, not exported plugin interfaces. Their existence proves Niles itself can perform these operations, not that an add-on can call them.
