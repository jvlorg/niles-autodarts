# Niles Autodarts — canonical plan

## GOAL STATUS

Implemented locally: validated announcement settings; an application session owning `LocalJourney`; bounded JSON parsing with automatic parse-error invalidation; reconfiguration and connection-reset handling; and bounded delivery attempts with unavailable and recording adapters. The component owns `/api/events` WebSocket ingress and a room-bound speech-stream adapter through its checked-in [Niles WIT imports and callbacks](../component/wit/niles-integration.wit) and [component lifecycle](../component/src/lib.rs). [Synthetic component-import tests](../component/src/tests.rs) cover this wiring. Maintained [replay](../crates/autodarts-core/examples/announcement_replay.rs) exercises settings → raw JSON → session → announcement request/result across three collections, including partial/full duplicates. Parser regressions retain rejection of segment numbers 21–24, unrelated event topics, and bounded attempt history.

Remaining proof: compatibility with an intended installed Niles host, actual Board Manager event delivery/order and miss encoding, and end-to-end audible output. Synthetic imports and compiled synthetic-host checks do not establish those behaviors. The local total is a detection-derived collection sum, not game-credited X01 authority. See [announcement path](announcement-path.md) for evidence boundaries.

## V1 — local Board Manager score announcements and detection control

V1 uses only the locally configured Autodarts Board Manager. No cloud account, match feed, X01 authority, game selection, match outcome or special/game speech is required. Local dart products and collection sums are not credited X01 scores, remaining scores, busts or checkout results.

The event parser accepts `{type,data}` envelopes and state fields `numThrows`, optional `throws[]`, and `segment.number`/`segment.multiplier`. It bounds envelope bytes and dart array length, rejects non-object states, invalid range/multipliers and count mismatches. Bull 25 and 50 are valid. Multiplier-zero is rejected; maintained source evidence does not resolve whether misses are encoded as `(0,0)` or `(0,1)`, so no claim of validated miss support is made. A malformed JSON input is reported by `AnnouncementSession` to the reducer as invalid; callers cannot silently drop parse errors through the session API.

Reducer phases are awaiting a clean baseline, collecting, and awaiting clear. Only an empty, count-zero state establishes a usable baseline. A nonempty baseline suppresses that entire existing collection, including later appends. Unrelated camera/status topics are ignored. It accepts one append at a time, with at most three darts. Each dart is announced as local API reports it; TotalOnly remains silent until the total boundary. The first explicit `isTakeoutPartial=true` or `isTakeoutFull=true` marker completes the eligible cached collection once; subsequent markers cannot repeat it. These are local detection values, not authoritative game scores.

For marker-before-clear, the validated cached collection is spoken once. In TotalOnly, a clear-before-marker preserves its eligible cached collection until the explicit removal marker; clear itself never announces. For Each dart → Total, if a shrink/empty state precedes the marker, retain only the last validated pre-removal snapshot as a bounded candidate; shrink alone never announces. The first subsequent explicit removal marker may complete that candidate. Corrections, invalid/out-of-order evidence, malformed/stopped input and reconnect/disable/settings changes invalidate it; ambiguity suppresses. After completion, require a clean empty baseline before another collection. No reliable timestamps are supplied by the source, so no time-based expiry is claimed.

`AnnouncementSession` owns validated settings, parsing and reducer state; callers provide each JSON envelope and an `AnnouncementDelivery`. Request keys include connection epoch and collection serial. Each delivery attempt is recorded before invoking the injectable boundary, so unavailable/failed attempts are not blindly retried. Target identities are sorted and deduplicated. Disabling, changing mode/audience, or reconnecting resets policy and requires a clean empty baseline. Parse failures automatically invalidate the current journey.

A slow `/api/state` timer poll is status/baseline-only, not a real-time event stream. When announcement intent is enabled, the component connects to local `/api/events` and passes frames through `AnnouncementSession::ingest_json`; the session delivery boundary connects to a room-bound speech stream when available. The separate `speech_stream_enabled` setting gates opening that stream, so event ingress does not establish speech availability. The component supports explicit unavailable and recording delivery boundaries. Remaining work is compatibility and live validation on the intended host; no Niles core edits, sidecar, notification fallback, or direct satellite transport. See [core communication](core-communication.md).

V1 product scope remains Board Manager detection on/off (not physical power/reset/game creation), room selection and local announcements through selected room satellites in both Each dart → Total and Total only modes; these are not all implemented end-to-end. Announcement settings default disabled; identities are configuration intent, not validated household targets. Preserve V2 TV scoreboard and V3 game selection as later scope; do not collapse those roadmap boundaries into V1.

## Verification and proof boundaries

Synthetic parser/session tests cover three identical consecutive collections, incremental speech, both modes, first partial/full removal exactly once, repeated markers, both clear/marker orders including TotalOnly clear-before-marker, correction/no-marker suppression, resets, bounded unique identities, parse-error invalidation, unavailable no-retry, and synthetic miss/bull cases (not live evidence). Maintained JSON replay exercises three collections through settings → session JSON ingress → reducer → recording adapter. `component/src/tests.rs` adds synthetic-import lifecycle, callback, settings-gate, reset, malformed-frame and cleanup coverage. The separate optional compiled-component host-proof fixture in `component/tests/host_proof.rs` uses loopback events and `RecordingSpeech`; execution is not established here. A successful run would provide synthetic host evidence, not installation or audibility. Its standalone `component/host-proof/Cargo.toml` depends on developer-local absolute paths to `niles-core` and `niles-plugins`; ordinary verification does not exercise this optional crate. The ordinary application verification chain and component tests were not run for this documentation reconciliation.

Keep source-implemented, synthetic-tested, host-tested, installed and live-proven distinct. Local documentation commits are authorized for JVL-10; publication belongs to its workflow stage. No live board command/observation, provider calls, audible test or deployment is part of this documentation reconciliation.
