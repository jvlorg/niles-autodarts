# Niles Autodarts — canonical plan

## GOAL STATUS

Implemented locally: validated announcement settings; transport-independent `AnnouncementSession` and `LocalJourney`; bounded JSON parsing with automatic parse-error invalidation; reconnect/reconfiguration resets; injectable unavailable and recording delivery; component WebSocket ingress; and an optional room-bound Niles speech stream. The component submits requests, tracks host IDs, polls every host outcome, preserves pending requests across polling errors, bounds terminal history, and discards stale generations on reset. The pinned host checkout, exact WIT comparison, release metadata, deterministic replay, callback regressions, package scripts, and approval-gated workflow are checked in. The alpha candidate remains local and is not an installed or published release.

Remaining evidence and product work: the compiled host proof requires the host checkout's native OpenSSL development dependency in this environment. Installed-host compatibility, live Board Manager event-order and miss-encoding observations, end-to-end/audible verification, and configured-audience-to-selected-satellite routing are not established. The room-bound speech API is Niles-owned and does not prove selected-satellite behavior. The slow `/api/state` poll remains status/baseline-only rather than a real-time event feed. The local total is a detection-derived collection sum, not game-credited X01 authority.

## V1 — local Board Manager score announcements and detection control

V1 uses only the locally configured Autodarts Board Manager. No cloud account, match feed, X01 authority, game selection, match outcome or special/game speech is required. Local dart products and collection sums are not credited X01 scores, remaining scores, busts or checkout results.

The event parser accepts `{type,data}` envelopes and state fields `numThrows`, optional `throws[]`, and `segment.number`/`segment.multiplier`. It bounds envelope bytes and dart array length, rejects non-object states, invalid range/multipliers and count mismatches. Bull 25 and 50 are valid. Multiplier-zero is rejected; maintained source evidence does not resolve whether misses are encoded as `(0,0)` or `(0,1)`, so no claim of validated miss support is made. A malformed JSON input is reported by `AnnouncementSession` to the reducer as invalid; callers cannot silently drop parse errors through the session API.

Reducer phases are awaiting a clean baseline, collecting, and awaiting clear. Only an empty, count-zero state establishes a usable baseline. A nonempty baseline suppresses that entire existing collection, including later appends. Unrelated camera/status topics are ignored. It accepts one append at a time, with at most three darts. Each dart is announced as local API reports it; TotalOnly remains silent until the total boundary. The first explicit `isTakeoutPartial=true` or `isTakeoutFull=true` marker completes the eligible cached collection once; subsequent markers cannot repeat it. These are local detection values, not authoritative game scores.

For marker-before-clear, the validated cached collection is spoken once. In TotalOnly, a clear-before-marker preserves its eligible cached collection until the explicit removal marker; clear itself never announces. For Each dart → Total, if a shrink/empty state precedes the marker, retain only the last validated pre-removal snapshot as a bounded candidate; shrink alone never announces. The first subsequent explicit removal marker may complete that candidate. Corrections, invalid/out-of-order evidence, malformed/stopped input and reconnect/disable/settings changes invalidate it; ambiguity suppresses. After completion, require a clean empty baseline before another collection. No reliable timestamps are supplied by the source, so no time-based expiry is claimed.

`AnnouncementSession` owns validated settings, parsing and reducer state; callers provide each JSON envelope and an `AnnouncementDelivery`. Request keys include connection epoch and collection serial. Each delivery attempt is recorded before invoking the injectable boundary, so unavailable/failed attempts are not blindly retried. Target identities are sorted and deduplicated. Disabling, changing mode/audience, or reconnecting resets policy and requires a clean empty baseline. Parse failures automatically invalidate the current journey.

A slow `/api/state` timer poll is status/baseline-only, not a real-time event stream. `AnnouncementSession` remains transport-independent; the component supplies `/api/events` ingress and an optional room-bound speech adapter through the pinned WebSocket and speech-stream imports. Announcement intent enables the event connection; `speech_stream_enabled` separately gates opening speech for the configured room. The component's request submission and status polling do not prove audible completion, compatible installed-host behavior, or selected-satellite routing. Keep household membership, audience resolution and speech authority in Niles. Retain the core's unavailable and recording adapters as injectable delivery choices; they are not the only behavior represented by the component. No Niles core edits, sidecar, notification fallback, or direct satellite transport.

V1 product scope remains Board Manager detection on/off (not physical power/reset/game creation), room selection and local announcements through selected room satellites in both Each dart → Total and Total only modes; these are not all implemented end-to-end. Announcement settings default disabled; identities are configuration intent, not validated household targets. Preserve V2 TV scoreboard and V3 game selection as later scope; do not collapse those roadmap boundaries into V1.

## Verification and proof boundaries

Core policy coverage remains specific: synthetic parser/session tests cover three identical consecutive collections, incremental speech, both modes, first partial/full removal exactly once, repeated markers, both clear/marker orders including TotalOnly clear-before-marker, correction/no-marker suppression, resets, bounded unique identities, parse-error invalidation, unavailable no-retry, and synthetic miss/bull cases (not live evidence). Parser/reducer regressions also cover rejection of segment numbers 21–24, ignoring unrelated event topics, and bounded attempt history across collection baselines. Maintained JSON replay exercises three collections through settings → session JSON ingress → reducer → recording adapter.

| Evidence path | Source and tests | What it establishes | What it does not establish |
|---|---|---|---|
| Core parser/session and maintained replay | `crates/autodarts-core/src/local_score.rs`, `crates/autodarts-core/examples/announcement_replay.rs`, and core tests | Parser/reducer/session policy on deterministic synthetic inputs; the replay carries settings through JSON ingress to recording requests/results | Component callbacks, host compatibility, live provider behavior, audience routing, or audible output |
| Component callbacks with fake WIT imports | `component/src/lib.rs`, `component/src/tests.rs`, and `component/src/test_host.rs` | Synthetic stale-connection filtering, valid text, binary/malformed-frame invalidation, reconnect/reconfiguration resets, speech request IDs, every released host outcome, polling recovery, oversized-frame rejection, and overflow recovery | Does not establish installed-host compatibility, live provider behavior, audience routing, or audible output |
| Compiled Niles runtime host proof | `component/tests/host_proof.rs`, `component/host-proof/Cargo.toml`, and `.cache/niles` at the pinned revision | Intended compiled WebSocket policy and speech path through `niles_plugins::Runtime`, with real Niles scheduler callbacks and synthetic recording output | Current environment is blocked before compilation by missing native OpenSSL development files; even a pass would not establish live provider events, household routing, or audibility |
| Exact package and loopback diagnostic | `scripts/package.sh`, `scripts/verify-host.py`, and `scripts/verify.sh` | Exact manifest/Wasm candidate, CLI package validation, and synthetic loopback HTTP rendering | No WebSocket ingress, speech lifecycle, live board behavior, audible delivery, installation, or publication evidence |

Source-implemented and synthetic-tested behavior must remain distinct from host-tested, installed and live-proven behavior. Installed-host compatibility, live event ordering/miss encoding, audible verification, and selected-satellite audience behavior are not established by the evidence above. Documentation reconciliation adds no installation, live/provider/device, deployment, release, or audible evidence.
