# Niles Autodarts — canonical plan

## GOAL STATUS

Implemented locally: validated announcement settings; a transport-independent application session owning `LocalJourney`; JSON parsing with automatic parse-error invalidation; reconfiguration and connection-reset handling; injectable delivery with explicit unavailable and recording adapters. The component opens optional WebSocket event ingress and a room-bound speech-stream session, routes bounded text callbacks through `AnnouncementSession`, handles connection/reset/reconfiguration lifecycle, submits and polls speech requests, and closes owned handles on stop. Synthetic component tests cover callback-to-speech behavior and lifecycle cases. The pinned contract and implementation are in [`component/src/lib.rs`](../component/src/lib.rs), [`component/wit/niles-integration.wit`](../component/wit/niles-integration.wit), and [`component/niles-integration.toml`](../component/niles-integration.toml); they describe this repository’s integration contract, not compatibility with an installed Niles version. Maintained replay exercises settings → raw JSON → session → announcement request/result across three collections, including partial/full duplicates. Parser regressions retain rejection of segment numbers 21–24, unrelated event topics, and bounded attempt history.

Still unproven: compatible installation, live Board Manager event ordering and miss encoding, actual household target resolution, end-to-end audio, and audibility. The local total is a detection-derived collection sum, not game-credited X01 authority.

## V1 — local Board Manager score announcements and detection control

V1 uses only the locally configured Autodarts Board Manager. No cloud account, match feed, X01 authority, game selection, match outcome or special/game speech is required. Local dart products and collection sums are not credited X01 scores, remaining scores, busts or checkout results.

The event parser accepts `{type,data}` envelopes and state fields `numThrows`, optional `throws[]`, and `segment.number`/`segment.multiplier`. It bounds envelope bytes and dart array length, rejects non-object states, invalid range/multipliers and count mismatches. Bull 25 and 50 are valid. Multiplier-zero is rejected; maintained source evidence does not resolve whether misses are encoded as `(0,0)` or `(0,1)`, so no claim of validated miss support is made. A malformed JSON input is reported by `AnnouncementSession` to the reducer as invalid; callers cannot silently drop parse errors through the session API.

Reducer phases are awaiting a clean baseline, collecting, and awaiting clear. Only an empty, count-zero state establishes a usable baseline. A nonempty baseline suppresses that entire existing collection, including later appends. Unrelated camera/status topics are ignored. It accepts one append at a time, with at most three darts. Each dart is announced as local API reports it; TotalOnly remains silent until the total boundary. The first explicit `isTakeoutPartial=true` or `isTakeoutFull=true` marker completes the eligible cached collection once; subsequent markers cannot repeat it. These are local detection values, not authoritative game scores.

For marker-before-clear, the validated cached collection is spoken once. In TotalOnly, a clear-before-marker preserves its eligible cached collection until the explicit removal marker; clear itself never announces. For Each dart → Total, if a shrink/empty state precedes the marker, retain only the last validated pre-removal snapshot as a bounded candidate; shrink alone never announces. The first subsequent explicit removal marker may complete that candidate. Corrections, invalid/out-of-order evidence, malformed/stopped input and reconnect/disable/settings changes invalidate it; ambiguity suppresses. After completion, require a clean empty baseline before another collection. No reliable timestamps are supplied by the source, so no time-based expiry is claimed.

`AnnouncementSession` owns validated settings, parsing and reducer state; callers provide each JSON envelope and an `AnnouncementDelivery`. Request keys include connection epoch and collection serial. Each delivery attempt is recorded before invoking the injectable boundary, so unavailable/failed attempts are not blindly retried. Target identities are sorted and deduplicated. Disabling, changing mode/audience, or reconnecting resets policy and requires a clean empty baseline. Parse failures automatically invalidate the current journey.

A slow `/api/state` timer poll is status/baseline-only, not a real-time event stream. The component’s WebSocket callback is the separate event ingress; its bounded text frames enter `AnnouncementSession`. A room-bound speech-stream adapter submits and polls requests and closes its session with the component lifecycle. These paths are defined by the pinned imports in [`component/wit/niles-integration.wit`](../component/wit/niles-integration.wit) and grants/settings in [`component/niles-integration.toml`](../component/niles-integration.toml). Speech request status is not proof of human audibility. The core still offers injectable recording and unavailable adapters; the component supplies the speech adapter. Niles retains household authorization, audience resolution and speech authority. No sidecar, notification fallback, or direct satellite transport is part of this design.

V1 product scope remains Board Manager detection on/off (not physical power/reset/game creation), room selection and local announcements through selected room satellites in both Each dart → Total and Total only modes; these are not all implemented end-to-end. Announcement settings default disabled; identities are configuration intent, not validated household targets. Preserve V2 TV scoreboard and V3 game selection as later scope; do not collapse those roadmap boundaries into V1.

## Verification and proof boundaries

|---|---|---|
| Core parser/session policy and three-collection replay are implemented; synthetic coverage exercises parsing, collection policy, resets and delivery requests. | [`component/src/tests.rs`](../component/src/tests.rs), [`announcement_replay.rs`](../crates/autodarts-core/examples/announcement_replay.rs) | Synthetic inputs only; no live Board Manager ordering or miss-encoding evidence. Replay models a detection-derived local total, not credited X01 authority. |
| Component callbacks route bounded WebSocket text through the session and exercise room speech open/submit/poll/close and lifecycle cases. | [`component/src/tests.rs`](../component/src/tests.rs), [`component/src/lib.rs`](../component/src/lib.rs), [`niles-integration.wit`](../component/wit/niles-integration.wit) | Synthetic host imports; does not prove an installed compatible Niles contract, real event delivery, household target resolution, audio or audibility. Text ingress is bounded to 64 KiB; binary frames and arbitrary payloads are not supported announcement inputs. |
| An optional real-host harness is available with recording speech. | [`host_proof.rs`](../component/tests/host_proof.rs), [`host-proof/Cargo.toml`](../component/host-proof/Cargo.toml) | Conditional harness path, not evidence of a fresh successful run. Its manifest directly uses absolute developer-local paths for `niles-core` and `niles-plugins`, so it is not portable from an arbitrary fresh checkout. Recording speech proves exercised host policy/lifecycle only, never audibility. |
| A loopback HTTP host diagnostic checks rendered status from synthetic `/api/version` and `/api/state` responses. | [`verify-host.py`](../scripts/verify-host.py) | Status-path evidence only; no event-stream, speech, live device, installation compatibility or audibility proof. |

[`verify.sh`](../scripts/verify.sh) defines the maintained workspace and Wasm verification chain; its existence is a verification path, not a claim that it was freshly run. Keep source-implemented, synthetic-tested, host-tested, installed compatible deployment, and live/audible proof distinct. Any previously recorded run should retain its original date, command and scope where recorded; no undated run summary establishes current completion.

Remaining work: verify installation against a compatible Niles version; observe live Board Manager event ordering and miss encoding (`(0,0)` versus `(0,1)` remains unresolved); verify actual household targeting; and establish end-to-end audio and human audibility. Do not infer these from a request submission, asynchronous status, synthetic fixture or local status poll.
