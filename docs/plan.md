## V1 — local Board Manager score announcements and detection control

V1 uses only the locally configured Autodarts Board Manager. No cloud account, match feed, X01 authority, game selection, match outcome or special/game speech is required. Local dart products and collection sums are not credited X01 scores, remaining scores, busts or checkout results.

The event parser accepts `{type,data}` envelopes and state fields `numThrows`, optional `throws[]`, and `segment.number`/`segment.multiplier`. It bounds envelope bytes and dart array length, rejects non-object states, invalid range/multipliers and count mismatches. Bull 25 and 50 are valid. Multiplier-zero is rejected; maintained source evidence does not resolve whether misses are encoded as `(0,0)` or `(0,1)`, so no claim of validated miss support is made. A malformed JSON input is reported by `AnnouncementSession` to the reducer as invalid; callers cannot silently drop parse errors through the session API.

Reducer phases are awaiting a clean baseline, collecting, and awaiting clear. Only an empty, count-zero state establishes a usable baseline. A nonempty baseline suppresses that entire existing collection, including later appends. Unrelated camera/status topics are ignored. It accepts one append at a time, with at most three darts. Each dart is announced as local API reports it; TotalOnly remains silent until the total boundary. The first explicit `isTakeoutPartial=true` or `isTakeoutFull=true` marker completes the eligible cached collection once; subsequent markers cannot repeat it. These are local detection values, not authoritative game scores.

For marker-before-clear, the validated cached collection is spoken once. In TotalOnly, a clear-before-marker preserves its eligible cached collection until the explicit removal marker; clear itself never announces. For Each dart → Total, if a shrink/empty state precedes the marker, retain only the last validated pre-removal snapshot as a bounded candidate; shrink alone never announces. The first subsequent explicit removal marker may complete that candidate. Corrections, invalid/out-of-order evidence, malformed/stopped input and reconnect/disable/settings changes invalidate it; ambiguity suppresses. After completion, require a clean empty baseline before another collection. No reliable timestamps are supplied by the source, so no time-based expiry is claimed.

`AnnouncementSession` owns validated settings, parsing and reducer state; the component passes callback envelopes into the session and supplies a room-bound speech adapter. Request keys include connection epoch and collection serial. Each delivery attempt is recorded before invoking the adapter, so unavailable/failed attempts are not blindly retried. The [settings and request types](../crates/autodarts-core/src/lib.rs) carry a single room whose syntax is validated; there is no selected-satellite list to sort, deduplicate or route. Calling the session’s `reconfigure` with changed enablement, mode or room, or calling `connection_reset`, resets policy and requires a clean empty baseline. Parse failures automatically invalidate the current journey.

The component validates the configured Board Manager endpoint and host permission grant before opening its host-managed WebSocket. Callback JSON enters the owned session; HTTP `/api/state` polling remains separate and status-only. A configured room speech stream is opened and used for eligible submissions. Connection status changes reset session policy and require a clean baseline; component `init` first closes active resources through `stop`, then rereads settings and creates a fresh session. Cleanup also closes active resources. Session-level `reconfigure` does not reopen streams, and no dynamic host settings callback is implemented. Announcement enablement and speech-stream enablement are independent switches, both disabled by default in [`component/niles-integration.toml`](../component/niles-integration.toml). Detection on/off is a separate Board Manager device action. See [`component/src/lib.rs`](../component/src/lib.rs), the [checked-in integration WIT](../component/wit/niles-integration.wit), and [WIT provenance](../component/wit/PROVENANCE.md). These describe the checked-in contract, not a guarantee about a released Niles API. The manifest's interface `0.5` declaration is separate from the WIT package version. The older root `manifest.toml` is not the active component configuration authority.

V1 product scope remains Board Manager detection on/off (not physical power/reset/game creation), room selection and local announcements through selected room satellites in both Each dart → Total and Total only modes. The implementation currently submits through a room-bound stream; fulfillment of a persisted selected-satellite subset remains unresolved. Announcement settings default disabled; room syntax validation does not establish household authorization or selected-satellite fulfillment. Preserve V2 TV scoreboard and V3 game selection as later scope; do not collapse those roadmap boundaries into V1.

## Verification and proof boundaries

The following evidence categories are distinct. Maintained tests describe intended coverage; any previously reported command run is historical evidence and is not a claim that this documentation change reran it.

- **Core parser/session tests and deterministic replay:** Tests in [`local_score.rs`](../crates/autodarts-core/src/local_score.rs) and [`announcement_session.rs`](../crates/autodarts-core/src/announcement_session.rs), together with [`announcement_replay.rs`](../crates/autodarts-core/examples/announcement_replay.rs), cover three identical consecutive collections, incremental speech, both modes, first partial/full removal exactly once, repeated markers, both clear/marker orders including TotalOnly clear-before-marker, no-marker suppression, resets, bounded unique identities, parse-error invalidation, unavailable no-retry, and synthetic miss/bull cases. Correction suppression is implemented in `LocalJourney::state`, but the maintained tests do not directly exercise corrected dart values. Replay carries validated settings and synthetic JSON through session ingress, reducer, and recording adapter over three collections. This is synthetic policy/request evidence, not live device or speech proof.
- **Component synthetic host imports:** [`component/src/tests.rs`](../component/src/tests.rs) and [`test_host.rs`](../component/src/test_host.rs) cover connection URL selection, room lifecycle, callback-driven announcements, disconnect/rebaseline, malformed frames, and cleanup with test doubles. This establishes simulated import behavior only.
- **Optional synthetic Niles runtime/Wasm harness:** [`component/tests/host_proof.rs`](../component/tests/host_proof.rs) installs built Wasm in a locally constructed Niles `Runtime`, with loopback HTTP/WebSocket fixtures and `RecordingSpeech`, for both modes. [`component/host-proof/Cargo.toml`](../component/host-proof/Cargo.toml) has absolute developer-local `/home/jleth/projects/niles-nil43` Rust crate paths. See the README for execution prerequisites. The harness is optional, nonportable as configured, and does not establish released/installed compatibility or audible output.
- **CLI synthetic HTTP/dry-run and loopback probe checks:** [`scripts/verify-host.py`](../scripts/verify-host.py) uses a supplied Niles CLI dev host with synthetic HTTP and dry-run diagnostics; [`scripts/test_probe_board.py`](../scripts/test_probe_board.py) covers loopback probe behavior. Each proves only its exercised synthetic path.
- **Default verification procedure:** [`scripts/verify.sh`](../scripts/verify.sh) documents format, build, Clippy, workspace tests, and release component build; optional host proof requires an executable host argument. These are procedures, not runs performed for this documentation change.
- **Not established:** compatible installed-host operation, real Board Manager event ordering/removal/miss encoding, selected-satellite subset fulfillment, household routing, or heard/audible speech.

Keep source-implemented, synthetic-import-tested, synthetic-runtime-tested, CLI/probe-tested, installed, live-proven and audible distinct. No credentials, household captures or local configuration belong in Git. No live board command/observation, provider call, deployment, or Niles core edit is part of this documentation reconciliation.
