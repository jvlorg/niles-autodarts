# Niles Autodarts

Standalone Niles add-on for local Autodarts Board Manager status and detection control, with an implemented component path for local score announcements. Component `Runtime` owns the `AnnouncementSession`, WebSocket state, and optional room-bound speech-stream state. When announcements are enabled, bounded Board Manager WebSocket callbacks feed the session; speech-stream delivery is separately configured. Both controls default disabled. This is source implementation with maintained synthetic coverage, not proof of a compatible installed host, live Board Manager event behavior, or audible output. See the [canonical plan](docs/plan.md) for detailed policy and remaining evidence.

The add-on validates local `{type,data}` event envelopes and local dart products. It does not depend on cloud authentication, X01 match authority, game selection, match outcomes, or special/game speech. Local dart values and collection sums are not credited X01 scores, remaining scores, busts, or checkout results. Bull numbers 25 and 50 are valid. Multiplier zero is rejected; live miss encoding remains unresolved.

The reducer requires a clean empty/count-zero baseline. A nonempty starting collection and later appends are suppressed. It processes at most three darts, one at a time. Each dart → Total can speak each detected local dart and completes the cached collection once at the first explicit partial/full removal marker; Total only stays silent until that boundary. Duplicate markers do not repeat a collection. Clear/shrink alone never announces a total. Ordering ambiguities, corrections, invalid input, reconnect, disable, or settings changes invalidate candidates and require a clean baseline. No timeout is inferred without reliable source timestamps.

The slow `/api/state` timer poll serves status/baseline handling and is not a real-time event feed. Detection on/off controls Board Manager detection only; it does not control physical power/reset or create a game. V1 includes room selection and local announcements through selected room satellites in Each dart → Total and Total only modes, subject to live/product validation. Configured audience identities are intent; Niles retains household validation and speech authority. V2 TV scoreboard and V3 game selection remain later roadmap scope.

For architecture and evidence limits, see [core communication](docs/core-communication.md), [announcement path](docs/announcement-path.md), and [canonical plan](docs/plan.md). The historical [framework checkpoint](docs/niles-framework-checkpoint.md) records earlier contract research, not current installed-host proof.

## Verification and proof boundaries

The repository keeps several distinct kinds of evidence:

- Core unit tests and the [`announcement_replay` example](crates/autodarts-core/examples/announcement_replay.rs) exercise deterministic synthetic settings, JSON, session/reducer policy, and a recording adapter. Replay does not exercise component or host transport.
- [`component/src/tests.rs`](component/src/tests.rs) uses mock imports to cover component configuration/lifecycle and callbacks. It is not an installed Niles host.
- [`scripts/verify-host.py`](scripts/verify-host.py) checks synthetic local HTTP GETs and rendered status through `plugin dev --dry-run --allow-loopback`; it does not test WebSocket event delivery, speech, a live board, or audibility.
- The optional [`component/tests/host_proof.rs`](component/tests/host_proof.rs) exercises a compiled component under a local Niles runtime with synthetic loopback events and recording speech. The separate [`component/host-proof/Cargo.toml`](component/host-proof/Cargo.toml) currently points to absolute dependencies under `/home/jleth/projects/niles-nil43/...`. A fresh checkout or arbitrary Niles executable alone is insufficient to build it. `scripts/verify.sh --host-proof /absolute/path/to/niles` gates this test after the normal verification chain and checks that the argument is executable; the argument does not select or replace the manifest's dependency paths.

`bash scripts/verify.sh` runs formatting, workspace build, strict Clippy, workspace tests, and a release Wasm component build. To request the optional compiled-component host proof, use `bash scripts/verify.sh --host-proof /absolute/path/to/niles`, subject to the local source dependency prerequisite above. `python3 scripts/verify-host.py /absolute/path/to/niles` runs the separate synthetic local HTTP/status check. The [WIT provenance](component/wit/PROVENANCE.md) describes the pinned contract source; it does not establish an installed or released compatible host. None of these paths proves live Board Manager ordering/miss encoding or audible playback.

The previous publication note reported `bash scripts/verify.sh` passing formatting, workspace build, strict Clippy, 36 unit tests, and release Wasm build, as well as the maintained replay and eight loopback probe tests. Those are historical reported results, not checks run for this documentation reconciliation; the optional host proof is separate. No secrets, household captures, or local configuration belong in Git.
