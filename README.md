# Niles Autodarts

Standalone Niles add-on for local Autodarts Board Manager status, detection control and local score announcements. Component WebSocket ingress and a room-bound speech-stream lifecycle are implemented and synthetically covered. Compatible installation, live event behavior, household targeting and audible operation remain unproven; see the [canonical plan](docs/plan.md) for scope and evidence limits.

The component keeps three paths distinct: timer-driven HTTP `/api/version` and `/api/state` polling updates status without feeding or resetting the announcement session; WebSocket text callbacks supply bounded event envelopes, including the required clean empty baseline, to the announcement session; and a room-bound speech stream submits and polls speech requests. The pinned contract is in [`component/wit/niles-integration.wit`](component/wit/niles-integration.wit), component lifecycle and adapters are in [`component/src/lib.rs`](component/src/lib.rs), and grants/settings are in [`component/niles-integration.toml`](component/niles-integration.toml). This repository contract does not establish compatibility with an installed Niles version. Speech request status does not establish human audibility.

Announcement settings and speech-stream enablement are separate, and both default disabled. The configured room expresses intent, not proof of household resolution; the component speech stream selects that one room and has no satellite-subset selector. Niles retains household authorization, room resolution and speech authority.

The parser validates local `{type,data}` envelopes and dart products without cloud authentication, X01 match authority, game control or game outcomes. Local totals are simple detection-derived sums, not credited scores, remaining scores, busts or checkout results. Bull scores 25/50 are valid (`segment.number=25` with multiplier 1 or 2). Segment numbers 21–24, multiplier zero, invalid ranges and count mismatches are rejected. Live miss encoding `(0,0)` versus `(0,1)` remains unresolved; synthetic miss fixtures do not validate live support.

Announcement policy remains local: Each dart → Total announces each locally reported dart and the eligible cached collection at the first explicit partial/full removal marker; Total only waits for that marker. Clear or shrink alone never announces. Marker-before-clear and clear-before-marker are handled with bounded pre-removal candidates; corrections, invalid/out-of-order evidence, malformed or stopped input, and reconnect/disable/settings changes invalidate uncertain candidates. Duplicate markers are suppressed, and another collection requires a clean empty/count-zero baseline. At most three darts are accepted. Request keys include connection epoch and collection serial, and attempts are recorded before delivery to avoid blind retries. No time-based expiry is claimed without reliable timestamps. These local rules are not proof of universal Board Manager semantics.

V1 covers Board Manager detection on/off (not physical power, reset or game creation), room-selection intent and local announcements in Each dart → Total and Total only modes, subject to the installation and proof limits above. Selected-satellite targeting remains unresolved because the current speech contract selects only one room. V2 TV scoreboard and V3 game selection remain later roadmap scope.

Synthetic core policy tests are maintained in [`local_score.rs`](crates/autodarts-core/src/local_score.rs) and [`announcement_session.rs`](crates/autodarts-core/src/announcement_session.rs); [`announcement_replay.rs`](crates/autodarts-core/examples/announcement_replay.rs) exercises three collections. Run the replay with `cargo run -q -p autodarts-core --example announcement_replay`. Synthetic component callback-to-speech lifecycle coverage is in [`component/src/tests.rs`](component/src/tests.rs). The optional real-host harness uses recording speech ([`host_proof.rs`](component/tests/host_proof.rs)); its manifest has absolute developer-local Niles dependencies, so it is not portable from a fresh checkout as checked in. The loopback HTTP diagnostic ([`verify-host.py`](scripts/verify-host.py)) covers only synthetic status responses and rendered status. These distinct paths do not establish compatible installation, live event ordering/miss encoding, household targeting, end-to-end audio or audibility.

See the [core communication inventory](docs/core-communication.md), [announcement path boundary](docs/announcement-path.md), and [historical framework checkpoint](docs/niles-framework-checkpoint.md).

## Verification

Run `bash scripts/verify.sh` for the maintained Rust workspace/Wasm chain (format, workspace build, Clippy, workspace tests and release Wasm build). The optional branch is `bash scripts/verify.sh --host-proof /absolute/path/to/niles`; it runs the host-proof test after the normal chain. The executable argument does not relocate its dependencies: [`component/host-proof/Cargo.toml`](component/host-proof/Cargo.toml) directly points `niles-core` and `niles-plugins` at absolute paths in a developer-local Niles checkout, so this optional crate is not portable or runnable from an arbitrary fresh checkout as checked in. Its recording speech adapter covers only exercised host policy/lifecycle behavior, not audibility.

`python3 scripts/verify-host.py /absolute/path/to/niles` exercises the built component against loopback synthetic HTTP for `/api/version` and `/api/state`, then checks rendered status. It does not exercise the WebSocket event path or speech. `uv run --with websockets==15.0.1 python scripts/test_probe_board.py` covers the separate synthetic probe path. These commands describe available verification paths; no fresh successful run is implied here. Keep credentials, household captures and local configuration out of Git.

The canonical plan preserves the [historical publication verification record](docs/plan.md#verification-and-proof-boundaries), including its command and synthetic scope; those results do not imply a fresh run.
